# STREAM UG

STREAM UG is a movie/media streaming web app with two sides: an **Admin Panel**
for managing content and a **User Panel** for browsing and watching content.

This repository contains the initial MVP skeleton, built with **React + TypeScript + Vite**
and client-side routing via **react-router-dom**. All data is currently backed by
in-memory mock data (see `src/data/mockData.ts`) so the app is demonstrable
immediately; it is structured so a real backend/API can be plugged in later.

## Getting started

```bash
npm install
npm run dev      # start the dev server
npm run build    # type-check and build for production
npm run lint     # lint with oxlint
```

## Connecting Supabase

The app can run entirely on mock data, or connect to a real
[Supabase](https://supabase.com) project for persistent storage and auth:

1. Copy `.env.example` to `.env`.
2. In your Supabase project dashboard, go to **Project Settings → API** and
   copy the **Project URL** and **anon public** (or **publishable**) key into
   `.env` as `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
   `VITE_SUPABASE_URL` must be the **base project URL**
   (e.g. `https://xxxxxxxx.supabase.co`) — do **not** append `/rest/v1/` or
   any other API path to it; the Supabase client library adds that itself.
3. Run the starter schema in `supabase/schema.sql` (Supabase SQL editor or
   CLI) to create the `profiles`, `content_types`, `categories`, `content`,
   `movie_requests`, `ratings`, `favorites`, `view_history`, `search_logs`,
   and `notifications` tables, RLS policies, and the `handle_new_user`
   trigger that creates a `profiles` row whenever someone signs up.
4. In **Authentication → Providers**, make sure **Email** sign-in is enabled.
   If you want new accounts to be usable immediately in development, you can
   disable "Confirm email" under **Authentication → Settings**; otherwise
   users must click the confirmation link Supabase emails them before they
   can log in.
5. To grant Admin Panel access, set `is_admin = true` on a user's row in
   `public.profiles` from the Supabase SQL editor/dashboard (never from the
   frontend) — e.g. `update public.profiles set is_admin = true where email = 'you@example.com';`.
6. Restart `npm run dev`.

When the env vars are set:
- `src/context/AppStateContext.tsx` loads content, categories, content types,
  movie requests, ratings, favorites, view history, search logs, and
  notifications from Supabase via the data-access layer in `src/api/`, and
  writes (new content, requests, ratings, favorites, etc.) are persisted
  there too, with `id`s generated by the database instead of the client.
- `login`/`signup`/`logout` use **Supabase Auth** (`supabase.auth.*`) instead
  of the mock `accounts` array, and the signed-in user's profile and admin
  flag are loaded from the `profiles` table (see `src/api/profileApi.ts`).
  Changing username/password and deleting the account (from Account
  Settings) also go through `profileApi.ts`/Supabase Auth. Note: deleting an
  account only removes the `profiles` row from the client (the anon key
  can't delete `auth.users`); pair this with a periodic backend job if you
  need full `auth.users` cleanup.
- The Admin Panel routes/nav link are only shown to users whose profile has
  `is_admin = true`; this is enforced both client-side (`ProtectedRoute`,
  `Navbar`) and via Supabase RLS policies, so it can't be bypassed from the
  browser.

Without the env vars, everything falls back to the mock data/mock auth in
`src/data/mockData.ts` and `src/context/AppStateContext.tsx`, so the app keeps
working out of the box for local development without a Supabase project.

## Admin access

The app reserves `admin@stream.com` as the admin login. How you set its
password depends on whether Supabase is connected:

- **With Supabase connected (recommended):** sign up normally with
  `admin@stream.com` through the app's Sign Up page (this lets *you* choose
  the password — it's never stored in source), then run step 5 above
  (`update public.profiles set is_admin = true where email = 'admin@stream.com';`)
  to grant it Admin Panel access.
- **Without Supabase (mock/local-dev mode):** set `VITE_MOCK_ADMIN_PASSWORD`
  in your `.env` (copy `.env.example` if you haven't) to bootstrap a local
  password for `admin@stream.com`, then restart `npm run dev`. Without this
  variable set, the mock admin account has no usable password and can't be
  logged into — no admin password is ever hardcoded in source
  (see `src/data/mockData.ts`).

Either way, once `admin@stream.com` is signed in it lands in the Admin Panel
because its `isAdmin`/`is_admin` flag is `true`.

## Project structure

```
src/
  types/                 Shared data models (Content, Category, ContentType,
                          MovieRequest, Rating, Favorite, ViewHistoryEntry,
                          SearchLogEntry, Notification, User, ...)
  data/mockData.ts        Sample/mock data covering every required category
  lib/supabaseClient.ts    Reusable Supabase client (reads env vars, see
                          "Connecting Supabase" below)
  api/                     Data-access layer; reads/writes Supabase when
                          configured, otherwise falls back to mock data
  context/AppStateContext.tsx
                          App state (content, ratings, requests, favorites,
                          view history, search logs, notifications) shared
                          across Admin & User panels; loads from `src/api/`
                          on mount
  utils/recommendations.ts
                          Recommendation algorithm scaffold based on ratings
                          and category affinity
  utils/analytics.ts       Admin engagement analytics (most rated/watched/
                          searched, trending requests, most favorited) and
                          the `getWatchCounts`/`formatCompactCount` helpers
                          used to show per-title watch-count badges
  utils/collections.ts     Shared builders for the Home page's rails
                          (trending, popular, recently added, recommended,
                          continue watching, recently viewed), reused by
                          `ExplorePage` so "Explore more" shows the same
                          ordering as the row it came from
  components/             Shared UI: Navbar (search with live suggestions,
                          notifications, profile menu), layouts, ContentCard
                          (poster + watch-count badge), CategoryRow
                          (horizontal rail with an optional "Explore more"
                          link), WatermarkedVideo, TrailerMarquee
                          (autoplay-on-scroll), RatingStars
  pages/landing/           Public Home/Landing page shown to signed-out
                          visitors at `/`, with links to Login and Signup
  pages/auth/              Login (`/login`) and Signup (`/signup`) pages
  pages/user/              User Panel web pages (mounted under `/browse`):
                          Browse (horizontal rails, trailer marquee, genre
                          filter/sort), Content detail/watch page (trailer
                          preview toggle, related/recommended rails), Movie
                          request form, Trailers search page, full rail/genre
                          listing (`ExplorePage`, "Explore more"), site-wide
                          search results (`SearchResultsPage`), My Watchlist
                          (requests/uploaded-for-me/recommended/favorites),
                          Account Settings (username/password/delete account)
  pages/admin/             Admin Panel web pages (mounted under `/admin`):
                          Dashboard, Content list, Content upload/edit form
                          (incl. watermark settings), Content Types manager,
                          Categories view, Movie requests review (incl.
                          linking a request to uploaded content, which
                          notifies the requester), Analytics
```

## Routes

| Route                          | Access             | Page                                   |
| ------------------------------- | ------------------ | --------------------------------------- |
| `/`                              | public             | Home / landing page                     |
| `/login`                         | public             | Login                                   |
| `/signup`                        | public             | Signup (username, email, password)      |
| `/browse`                        | signed-in          | User Panel: browse content              |
| `/browse/watch/:contentId`       | signed-in          | User Panel: watch/content detail        |
| `/browse/requests`               | signed-in          | User Panel: submit a movie request      |
| `/browse/trailers`               | signed-in          | User Panel: search & preview trailers   |
| `/browse/watchlist`              | signed-in          | User Panel: My Watchlist / My Requests  |
| `/browse/explore/:key`           | signed-in          | User Panel: full listing for a rail/genre ("Explore more") |
| `/browse/search`                 | signed-in          | User Panel: search results (`?q=`)      |
| `/browse/account`                | signed-in          | User Panel: Account Settings            |
| `/admin`, `/admin/*`             | signed-in          | Admin Panel dashboard & management pages |
| `/admin/analytics`               | signed-in admin    | Admin Panel: engagement analytics       |

## Feature coverage

**Admin Panel**
- Upload/edit content: title, description, content type, trailer, full video,
  watermark settings, category (`pages/admin/AdminContentFormPage.tsx`)
- Create/manage content types (`pages/admin/AdminContentTypesPage.tsx`)
- Create categories and view content grouped by category
  (`pages/admin/AdminCategoriesPage.tsx`, `pages/admin/AdminContentListPage.tsx`)
- View & update movie requests submitted by users, and link a request to the
  content uploaded to fulfill it — which notifies the requester
  (`pages/admin/AdminRequestsPage.tsx`)
- Engagement analytics: most rated/highest rated/most watched/most searched
  movies, trending (duplicate) requests, and most favorited movies
  (`pages/admin/AdminAnalyticsPage.tsx`, `utils/analytics.ts`)

**User Panel**
- Browse content grouped into horizontally-scrollable rails/rows: Trending
  Now, Continue Watching, Popular on STREAM UG, Recommended For You, Recently
  Added, Recently Viewed, and one row per category, covering all requested
  categories (translated movies, local music/audio, comedy, cartoons, sports
  & football analysis, non-translated movies, anime, campus entertainment,
  local soaps/series, news, talk shows, Nigerian/Indian/Korean/Chinese
  movies, telenovelas). Each rail has an "Explore more" link
  (`pages/user/ExplorePage.tsx`) that opens a full grid of that rail/genre.
  A genre filter + sort (trending/newest/top rated/title) control sits over
  the full catalog at the bottom of the page.
- Every poster shows a watch-count badge (👁 count of distinct viewers,
  compactly formatted e.g. `1.2K`), derived from `view_history`
  (`utils/analytics.ts#getWatchCounts`), on cards throughout the app
- Site-wide search: a search box in the header offers live title suggestions
  and submits to a full search-results page matching title/description/genre
  (`components/Navbar.tsx`, `pages/user/SearchResultsPage.tsx`), logging
  each query for the "most searched" admin analytic
- Watch page with watermark overlay, star ratings, a "Watch Trailer" toggle
  to preview the trailer before committing to the full video, an "Add to
  Watchlist" (favorite) toggle, a watch-count badge, and "More <Genre>" /
  "Recommended For You" related-content rails; watch progress is recorded
  for Continue Watching
- Trailers page: search any title and preview its trailer
  (`pages/user/TrailersPage.tsx`)
- My Watchlist / My Requests page: movies requested, movies uploaded to
  fulfill a request, movies suggested/recommended, and favorites
  (`pages/user/WatchlistPage.tsx`)
- Submit movie requests, and see them fulfilled/notified when uploaded
- Notifications bell in the header for request-fulfilled alerts
- Profile menu in the header: Account Settings (change username, change
  password, delete account) and Log Out (`pages/user/AccountSettingsPage.tsx`)

**Cross-cutting features**
- Watermarks rendered over video playback (`WatermarkedVideo`)
- Trailer marquee: trailers auto-play as users scroll them into view
  (`TrailerMarquee`, using `IntersectionObserver`)
- Movie ratings (`RatingStars`) feed a simple recommendation scaffold
  (`utils/recommendations.ts`) that can be replaced with a real algorithm later
- All signed-in users can browse the full app and play full videos

This is an MVP scaffold: forms currently write to in-memory state only, and
mock media URLs are used as placeholders. Wiring these to a real backend/API
and persistent storage is expected as a follow-up.
